# Data model: The door, the lobby, challenges and presence

The migration is `supabase/migrations/20260925001_door_lobby.sql`. It is additive: it adds one table, a handful of columns, eleven new functions and two changed ones, and drops nothing.

## Tables and columns

### `presence_tabs` (new)

| Column | Type | Notes |
|---|---|---|
| `tab_id` | uuid PK | Generated by the tab. Kept in `sessionStorage`, so it survives a reload of the same tab |
| `player_id` | uuid FK → players, on delete cascade | |
| `language` | text check in ('is','en') | Copied from `players.lobby_language` at each beat, never from the page |
| `page` | text check in ('lobby','profile','rules','match','other') | Informational; `match` marks the match page |
| `visible` | boolean | |
| `hidden_since` | timestamptz null | Set when `visible` turns false; null while visible |
| `last_input_at` | timestamptz null | Clamped to at most now |
| `cadence_ms` | int check in (10000, 30000) | |
| `beat_at` | timestamptz | `now()` at each heartbeat |
| `leaving_at` | timestamptz null | Set by the `pagehide` beacon; cleared by the next beat |

Indexes: `(player_id)`, `(language, beat_at desc)`. RLS: enabled with no anon policies; only the service role writes.

**Freshness.** A tab is fresh when `beat_at > now() − (3 × cadence_ms + 5000) ms` and not (`leaving_at < now() − 8s`). Rows that have been stale for more than 10 minutes are deleted by the sweep.

### `players`

| Column | Change |
|---|---|
| `lobby_language` | NEW text null, check in ('is','en'). Set by `enter_lobby` / `confirm_lobby_switch` |
| `unseen_result_match_id` | NEW uuid null FK → matches, on delete set null. "Your match is over", shown until the result is opened |
| `attention_*` (spec 069) | Now also written by the presence heartbeat: the best of the player's fresh tabs |

### `lobby_presence` (kept as the per-player summary)

The heartbeat keeps `language`, `mode='auto'` and `updated_at`. It sets `expires_at` to the latest gone deadline over the player's fresh tabs. `mode='direct_invite'` is no longer written when sending.

### `match_invitations`

| Column | Change |
|---|---|
| `status` | Check widened with `'left'`: pending, accepted, declined, expired, withdrawn, superseded, left |
| `expires_at` | NEW timestamptz not null default `now() + interval '60 seconds'`. Existing rows are backfilled with `created_at + 30s` (so they are all past) |
| `responded_at` | Existing column. Now set on every terminal status, and used for the 4s outcome window and the cooldowns |
| `auto_declined` | NEW boolean not null default false. Marks a challenge silenced by the three-declines rule |

Indexes: `(sender_id, created_at desc)` for the 6-per-minute limit; `(sender_id, recipient_id, status, responded_at desc)` for the cooldown and three-declines checks; `(recipient_id) where status='pending'`.

### `match_heartbeats`

| Column | Change |
|---|---|
| `source` | NEW text not null default 'match', check in ('match','page') |
| `cadence_ms` | NEW int not null default 2000. The match poll writes 2000; a page writes its tab cadence |

### `matches`

Two partial indexes for the head-to-head read: `(player_a_id, language) where state='completed'` and `(player_b_id, language) where state='completed'`.

## Functions

Each is `security definer` with `set search_path = public`, and executable by the service role only. Each lock order is players (in id order) before the match or the invitation, following stages 1 and 3.

| Function | Returns | Purpose |
|---|---|---|
| `beat_tab(p_player, p_tab, p_visible, p_input_ago_ms, p_page, p_cadence_ms)` | `(transition boolean, language text)` | Upserts the tab and refreshes `lobby_presence` and the attention columns. `transition` is true when the player had no other fresh tab before this beat, or when `visible` changed. |
| `leave_tab(p_player, p_tab)` | void | Sets `leaving_at = now()`. |
| `player_presence(p_language)` | setof `(player_id, state, moves_played, queued boolean)` | The derived state per player with a fresh tab in that lobby (US6.2). `in_match` comes from `matches` (pending or in progress), never from `players.status`. |
| `lobby_counts(p_language)` | `(here, searching, players_in_match, matches_on)` | Counts over `player_presence`. `players_in_match` counts players at a table or in a match (the lobby caption); `matches_on` counts matches in progress in that language (the door's masthead). |
| `head_to_head(p_viewer, p_language)` | setof `(opponent_id, wins, losses, draws)` | Over completed, non-void matches in that language. |
| `enter_lobby(p_player, p_language)` | `(status 'switched' \| 'same' \| 'needs_confirm', pending text[])` | `pending` lists the things a switch would cancel: `search`, `outgoing`, `incoming`. |
| `confirm_lobby_switch(p_player, p_language)` | void | Cancels the search, withdraws the outgoing challenge, ends incoming challenges as `left`, and switches the language. |
| `send_challenge(p_sender, p_recipient)` | `(status, invite_id, match_id, until)` | See the statuses below. Uses the sender's `lobby_language`. |
| `withdraw_challenge(p_sender, p_invite)` | `(status 'withdrawn' \| 'not_pending')` | A compare-and-set from pending to withdrawn. |
| `expire_challenges()` | setof `(invite_id, sender_id, recipient_id)` | Pending past `expires_at` become expired. |
| `settle_gone_players()` | setof `player_id` | Players with no fresh tab and a search or a pending challenge: the search is cancelled, and their challenges (sent and received) become `left`. |
| `accept_invite` (changed) | as before, plus `'gone'` | Refuses when the sender has no fresh tab: the invite becomes `left`, and the recipient reads `Kári has left · challenge withdrawn`. Also refuses an invite past `expires_at`. |
| `create_match_between` (changed) | as before | Ends the players' other pending incoming challenges as `superseded` (already), and clears `unseen_result_match_id` for both. |

`send_challenge` returns one of these statuses:

| Status | Meaning |
|---|---|
| `sent` | The challenge was recorded. |
| `crossed` | A reverse pending challenge existed, so the match was created through `accept_invite`. Returns `match_id`. |
| `in_match` | The recipient is at a table or in a match. |
| `gone` | The recipient has no fresh tab. |
| `away` | The recipient is away. |
| `other_lobby` | The two players are in different lobbies. |
| `cooldown` | The sender is in the table-leave cooldown. Returns `until`. |
| `declined_recently` | The pair is in its 60s decline cooldown. Returns `until`. |
| `rate_limited` | The sender has sent 6 challenges in the last minute. |
| `self` | The sender challenged themselves. |
| `busy_sender` | The sender is at a table or in a match. |

A silenced sender still gets `sent`. The row is written already `declined`, and the sender sees `declined` on their next standing read.

## Challenge state machine

```text
pending ──accept (recipient, CAS; sender fresh; before expires_at)──▶ accepted (match_id)
   │──decline (recipient)──────────────────────────────▶ declined   ─▶ pair cooldown 60s
   │──expires_at passes (sweep, or lazily on read)─────▶ expired    (`no answer`)
   │──withdraw ▸ / new challenge / search / accept / lobby switch / sign-out ─▶ withdrawn
   │──create_match_between for either player (paired, accepted another) ─▶ superseded (`started another match`)
   └──sender or recipient gone (settle_gone_players), or recipient switched lobby ─▶ left (`left the lobby`)
```

## Derived client models (`lib/types/standing.ts`, pure)

```ts
type PresenceState = "here" | "searching" | "in_match" | "away";

interface LobbyRow {
  playerId: string;
  displayName: string;
  handle: string;
  rating: number;
  state: PresenceState;
  movesPlayed: number | null;
  record: { wins: number; losses: number; draws: number } | null;
}

interface StandingFacts {
  now: string;                         // server time, for drift
  topic: string;                       // player:{hmac}
  lobbyLanguage: Language | null;
  incoming: Array<{ inviteId: string; from: LobbyRow; expiresAt: string }>;   // oldest first
  outgoing:
    | { inviteId: string; to: LobbyRow; status: InviteStatus; expiresAt: string; respondedAt: string | null; matchId: string | null }
    | null;
  cooldowns: Array<{ playerId: string; until: string }>;                      // decline cooldowns this viewer sent into
  search: { queuedAt: string; paused: boolean } | null;
  tableCooldownUntil: string | null;
  match:
    | { kind: "table" | "running"; matchId: string; opponent: string; movesPlayed: number; deadlineAt: string | null }
    | { kind: "over"; matchId: string; verdict: Verdict; detail: EndDetail }
    | null;
  switchPending: { to: Language; pending: Array<"search" | "outgoing" | "incoming"> } | null;
}

type SlotState =
  | { kind: "call"; invite: StandingFacts["incoming"][number]; more: number; searching: boolean }
  | { kind: "match"; match: NonNullable<StandingFacts["match"]> }
  | { kind: "switch"; to: Language; pending: Array<"search" | "outgoing" | "incoming"> }
  | { kind: "sent"; outgoing: NonNullable<StandingFacts["outgoing"]>; outcome: Outcome | null }
  | { kind: "search"; view: QueueView }            // spec 069's queueView: searching | stillSearching | paused | stopped | cooldown
  | { kind: "empty" };

type Outcome = "accepted" | "declined" | "no_answer" | "withdrawn" | "started_another" | "left";
```

`standingSlot(facts, nowMs, heldOutcome)` applies the precedence: `call` > `match` > `switch` > `sent` > `search` > `empty`. A `sent` outcome is held for 4s from `respondedAt` (400ms for `accepted`, followed by navigation).

## Validation rules

- The name input keeps spec 067's rule: 3–24 characters from letters, digits, `-` and `_`.
- `?next=` is accepted only when it starts with `/`, does not start with `//`, and its path, once the locale prefix is stripped, resolves to a known page (`/`, `/profile`, `/profile/:handle`, `/rules`, `/match/:uuid`). Anything else is dropped (`lib/auth/nextParam.ts`).
- Heartbeat inputs are parsed with Zod: `tabId` a uuid; `visible` a boolean; `inputAgoMs` an integer from 0 to 86,400,000; `page` from the enum.
